| ② | 聚类应能用训练出的小模型 | 模型是会话级、缺复用入口 | 新增 `components/teach_lab_model.py`（打分 UI + 批量打分）；🧩 聚类给**簇代表分子**打分；🧬 生成给候选打分筛选 | AppTest：聚类 10/10 打分成功（3 个 ≥0.5）；生成 5/5 成功（2 个 ≥0.5） |
| ③ | 分子对接提示「未检测到 Smina」 | **Smina 是 C++ 原生二进制，PyPI 上不存在 `smina` 包**（`pip install smina` → 404）；Streamlit Cloud 只跑 apt+pip，Debian 亦无此包 → 容器天然缺该二进制。**不是 Python 依赖冲突** | ①页面写明真因与三条可行路线；②`docking_utils.find_smina_executable()`（PATH → 当前/同机 conda 环境 → 常见系统路径）替换裸 `shutil.which`，消除"装了却检测不到"的误判；③`Dockerfile` 内置官方静态二进制（下载失败不影响构建）；④README 新增 FAQ | `find_smina_executable()` 命中 `…\envs\egfr-md\Library\bin\smina.exe`；官方静态包实测：下载 9.85 MB、`--version`/`--help` 返回 0、`ldd` 报 "not a dynamic executable"（无额外系统库依赖） |
| ④ | 分子生成为何不能"直接用"小模型 | 生成模型（字符级 LSTM，负责"写"）与判别模型（RF/GNN，负责"判"）任务不同，无法互相替代 | 页面内用表格讲清区别，并把小模型接成 **scorer**（REINVENT 的 generator + scoring function 分工）：生成 → 打分 → 排序 → 导出 | 生成页 AppTest：打分区块渲染、5/5 打分成功、解释面板存在 |

## 五、已知限制（明确写清，避免误用）

1. **Streamlit Community Cloud 无法运行分子对接**：Smina 为原生二进制，pip/apt 均无此包。云端请改用 `Dockerfile` 构建的镜像，或本地 conda 环境；其余页面云端不受影响（会自动降级提示）。
2. **内置预训练模型只覆盖 EGFR**（CHEMBL203，RF AUC ≈ 0.87 / GNN ≈ 0.85）：拿它预测其他靶点分子不具备科学意义；其他靶点请在 🎓 教学实验室现场训练。
3. **教学实验室的小模型是会话级**：保存在 `st.session_state`，刷新页面或点「重置」即失效，不落盘；跨会话复用需重新训练（教学上这正好体现"数据与模型的生命周期"）。
4. **教学实验室的 AUC 会虚高/波动**：测试集只有几十个样本，页面上已注明"要说明样本量"。
5. **待办（不影响结项）**：`environment_md.yml`（torch 2.1.2+cpu）与 `requirements.txt`（torch 2.5.1+cpu）版本声明仍未统一。
